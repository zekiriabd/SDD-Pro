# v7 Context Cache — Vestigial Design (Archived 2026-05-20)

> **Status** : Archived. **Not active**, **not loaded** by any agent,
> **not invoked** by any command. Preserved here for design archeology
> and potential future resurrection.

## What was this

A hash-based prompt-cache invalidation system designed to let agents
skip re-reading large static files (rules, stacks, architecture, QA
modes) when their content was unchanged across runs. Idea was :

1. Each "context family" (rules / stack / architecture / qa / session)
   has its content compiled into a single `*.digest.md` (~5-10 KB).
2. A `context-registry.json` indexes the digests with their sha256.
3. Agent reads the registry first (~1 KB). For each digest needed,
   it compares the hash against its last-seen value in conversation
   memory. Skip the Read on cache hit (Anthropic prompt cache serves
   the prior content within the 5min TTL).

5 cache layers planned :

| Key       | Digest                  | Refresh trigger        |
|-----------|-------------------------|------------------------|
| cache_001 | rules.digest.md         | `.claude/rules/*.md`   |
| cache_002 | stack.digest.md         | `stack.md` + stacks    |
| cache_003 | architecture.digest.md  | constitution + ADRs    |
| cache_004 | qa.digest.md            | QA modes + classes     |
| cache_005 | session.digest.md       | per-run, dynamic       |

## Why it landed here

Half-built. Only `cache_005` (session) had a working compiler
(`compile_session_digest.py`). The 4 stable digests (`rules`, `stack`,
`architecture`, `qa`) have output `*.digest.md` files in
`sample-outputs/` but **no compiler scripts** ever existed for them —
they were generated by hand or by a tool that wasn't committed. The
registry compiler (`compile_context_registry.py`) consumes whatever
digests it finds, so it kept "working" even with manual content.

**No agent ever read `context-registry.json`**. Grep across the
codebase 2026-05-20 returned only self-references inside the scripts'
own docstrings.

## Why we didn't finish it

v7.0.0 chose a simpler caching strategy : annotate
`reads:` entries in `loader.yml` with
`cache_layer: stable | semi | volatile` and let the harness emit
Anthropic `cache_control: ephemeral` markers at request build time
(cf. `loader.yml` lines 20-45, ADR `prompt-caching-strategy` if
present). Same goal (-30 to -50% Opus cost), simpler mechanism, no
extra compiler scripts to maintain, no extra digest files to keep in
sync. Native Anthropic semantics rather than custom registry.

## How to resurrect

1. Move `scripts/*.py` back to their original locations :
   - `compile_context_registry.py` → `.claude/python/sdd_scripts/`
   - `compile_session_digest.py` → `.claude/python/sdd_scripts/`
   - `session_context.py` → `.claude/python/sdd_lib/`
2. Write the 4 missing compilers (`compile_rules_digest.py`,
   `compile_stack_digest.py`, `compile_architecture_digest.py`,
   `compile_qa_digest.py`). Use `sample-outputs/*.digest.md` as the
   expected output format.
3. Add a STEP 0 to relevant agents (po/arch/dev-*/auditors) that
   reads `workspace/output/.sys/.cache/context-registry.json` and
   skips digest Reads on hash hit.
4. Add `compile_*` to a hook (PreToolUse Stop / PostToolUse) so the
   registry stays fresh — e.g. recompile on any `.claude/rules/*.md`
   write.
5. Consider whether the `cache_layer:` annotations in `loader.yml`
   already cover this — if yes, this resurrection adds maintenance
   cost without proportional gain.
